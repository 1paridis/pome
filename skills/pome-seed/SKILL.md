# pome-seed

播种需求。将一个需求拆解为一棵功能设计树，并为每个叶子节点写出技术设计，二者共同落在一份 `orchard.md` 中。

## 输入

进入 seed 的数据是一个需求，来源两种：

1. 用户直接提出的需求
2. 进行中的历史产物：`nursery` 下已存在该需求的 `orchard.md`，表示此前设计中断，需要续做而非从头开始

根节点由两部分组成：

- 简要标题：对需求的一句话总结
- 补充说明：对根节点需求的补充描述

## 拆解规则

以需求为根，按树状结构逐层展开，直到节点无法被分割为止。拆解顺序只是思考过程，不影响最终树的呈现。

「无法被分割」的判定：该节点对业务/用户仍有独立意义，且再往下拆就退化为实现步骤，无需再拆。

### 拆解门禁

拆解必须同时满足以下门禁，任一不满足即停止拆分或回退修正：

- **树高度 ≤ 3 层**：根为第 1 层，叶子最多到 `###`（三级标题）。若某个功能仍需第 4 层才能表达，说明根节点范围过大，应回退缩小根节点范围，而不是继续深挖。
- **子节点数量受限**：同一父节点下的子节点建议 2~7 个；超过 7 个通常意味着拆分粒度过细，应归并或上提；下限非强制，语义完整优先。

## 阶段一：功能设计

产出 `.pome/nursery/<需求简称>/orchard.md`：

- 用 Markdown 多级标题表示树的层级：根节点为 `#`，第二层为 `##`，以此类推，标题层级 = 树的深度
- 每个标题使用「点分序号 + 标题」编号：根为 `1`，子节点为 `1.1`、`1.2`，孙节点为 `1.1.1`，以此类推
- 根节点的补充说明写在根标题下方
- 分支节点：只有标题，不写说明
- 叶子节点：标题下方写一段简洁的功能说明

示例：

```markdown
# 1 需求标题

> 根节点需求的补充说明

## 1.1 子功能 A

### 1.1.1 叶子功能

简洁的功能说明。

### 1.1.2 叶子功能

简洁的功能说明。

## 1.2 子功能 B

### 1.2.1 叶子功能

简洁的功能说明。
```

### 讨论提问

拆解前若对需求有歧义，先集中向用户提问澄清，再开始拆解。可一次性提出多个问题，但同一批提出的多个问题之间不要互相影响：各问题独立作答，一个问题的答案不改变其他问题的答案。

### 阶段一门禁

- **编号与层级一致**：点分序号段数必须等于该节点的深度（根 `1` 一段、子 `1.1` 两段、孙 `1.1.1` 三段）。
- **叶子必有说明**：每个叶子节点都必须写功能说明；任何分支节点都不得出现说明文字。
- **说明只写「做什么」**：功能说明不得涉及实现（不写「如何做」）。

## 阶段二：技术设计

对功能设计中的每一个叶子节点做开发设计，把技术方案补写在对应叶子节点的「技术方案」小节内，仍落盘于 `.pome/nursery/<需求简称>/orchard.md`。

叶子节点的最终形态：

```markdown
### 1.1.1 叶子功能

功能说明：简洁的做什么。

**技术方案**

实现思路、涉及文件/模块、关键接口或数据结构、注意点……
```

技术方案正文示例：

```markdown
### 1.1.2 用户登录

功能说明：支持邮箱 + 密码登录，失败提示具体原因。

**技术方案**

在 `auth/login.py` 新增 `login(email, password)`，调用既有的 `User.query_by_email` 校验密码哈希，成功则签发 JWT（复用 `utils/jwt.py`），失败返回对应错误码。注意密码比对须用常量时间比较，避免时序攻击。
```

### 阶段二门禁

- **每个叶子都有技术方案**：所有叶子节点都须补写「技术方案」小节，不得遗漏。
- **不改功能设计**：补写技术方案时不得反向修改功能设计（功能说明、树结构）；若发现功能设计不合理，应先回阶段一修正再继续。
- **贴合实际技术栈**：技术方案必须贴合项目实际技术栈，不得虚构不存在的依赖、框架或模块。

## 产物结构

`<需求简称>` 采用 kebab-case 英文，如 `user-login`。

```
.pome
└── nursery
    └── <需求简称>
        └── orchard.md
```

## 执行流程

1. 确认需求：确定根节点的简要标题、补充说明，以及 `<需求简称>`（kebab-case 英文）
2. 断点续做检查：看 `.pome/nursery/<需求简称>/orchard.md` 是否已存在；存在则读取并续做未完成的部分（未拆完的分支继续拆、未写技术方案的叶子补齐），而非从头开始。
3. 功能设计：逐层拆解，生成 `orchard.md`
4. 技术设计：为功能设计中的每个叶子节点补写技术方案

### 流程门禁

- 阶段二必须在阶段一完成后进行。
- 每阶段完成后自检对应门禁，未通过则回退修正，不得进入下一阶段。
- 产物必须落盘到 `.pome/nursery/<需求简称>/` 下，文件名为 `orchard.md`。
