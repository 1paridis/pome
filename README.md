# pome

> **pome** -- 一枚石榴。石榴的籽本就是种子，果实落地不是结束，而是下一次生长的开始。pome 循着同样的心意：把 AI 辅助开发的流程，凝结成一粒粒独立可复用的 skill。
>
> 完整流程是 **Seed -> Plot -> pome-grow -> Reap**（播种 -> 规划 -> 生长 -> 收割）的流程化 skill 集合。

## 当前 skill

| Skill | 角色 |
|---|---|
| `pome-seed` | 需求设计起点：把需求收敛为一棵功能设计树 |
| `pome-plot` | 实现计划生成：把设计树重排为可执行、可验收的实施阶段 |
| `pome-grow` | 代码实现：以 blueprint 为目标，按 plan 阶段推进并在阶段间等待用户提交 |
| `pome-reap` | 需求归档：把 nursery 产物收割到按日期和需求名称组织的 archive 目录 |

## pome-seed

当用户提出新需求、需要需求拆解或功能设计时触发。它不急于写代码，而是先给出一个**设计树**：把需求拆解成功能单元，方案已明确的节点直接写方案，有分歧、缺信息或有风险的节点列出问题，整棵树交由用户逐点讨论、拍板。

### 设计树

- markdown 有序嵌套列表，节点带层级编号（1、1.1、1.2……），讨论时用编号直接定位
- 中间层节点是功能域，只起分组作用；叶子节点是能直接描述实现方案的最小单元
- 叶子节点名后的内容二选一：一句话方案（必要时附选择理由），或一个问题子列表
- 有问题的节点满足任一条件：**方向分歧**（多个互斥方向需用户拍板）、**信息不足**（缺关键信息给不出方案）、**技术风险**（依赖外部条件需用户知情确认）

### 工作流程

1. **检查**：`.pome/nursery/blueprint.md` 已存在时，先问用户继续原有需求的设计，还是开始新需求设计并覆盖原有 blueprint
2. **出树**：给出完整设计树，有问题的节点带问题子列表，供用户参考
3. **讨论**：用户用编号指定节点（如"讨论 1.3"），skill 说明待决定内容及可行选项；用户确认后把最终方案和必要理由写回节点
4. **收敛**：树上没有遗留问题时主动提示设计完成，完整展示最终设计树做最后确认
5. **落盘**：首次给出设计树时写入 `.pome/nursery/blueprint.md`，每次决策后立即更新

### 产物

`.pome/nursery/blueprint.md`，包含：

| 部分 | 内容 |
|---|---|
| 需求摘要 | 用户原始诉求的收敛表述 |
| 设计树 | 编号嵌套的功能方案与未决问题 |
| 遗留问题 | 未讨论的节点及其问题（没有则省略） |

## pome-plot

当 blueprint 已收敛、用户要求制定实现计划或准备开工时触发。它先勘察当前代码库，再把设计树重排为依赖递进、可独立验证的端到端阶段。每个阶段只交付一个可独立验收、提交和回退的结果；如果其中一部分可以先完成、独立验收并保持仓库有效，就继续拆成独立阶段。plan 记录稳定的实施边界，以及每个阶段覆盖的设计节点、前置依赖、交付能力和验收条件；具体文件路径、调用点和命令在开发时根据当前代码库确定，避免把容易过期的局部信息固化为契约。

修订已有 plan 时，已勾选项只有在当前代码仍满足修订后的交付和验收条件时才保留；受影响且无法证明仍成立的项目恢复为未完成，单纯的落点或命令变化不重置进度。

## pome-grow

当 blueprint 和 plan 已准备好、用户要求开始或继续实现时触发。它以 `.pome/nursery/blueprint.md` 作为功能方案、关键决策和范围边界的事实来源，以 `.pome/nursery/plan.md` 提供阶段覆盖、依赖和验收路径。pome-grow 一次完成一个阶段，阶段验收通过并更新进度后暂停，等待用户提交；用户确认提交后才进入下一阶段。阶段内的具体落点、步骤和命令根据代码库现实决定，只有计划结构无法覆盖方案时才返回 Plot，只有方案本身需要改变时才返回 Seed。

### 工作流程

1. **检查**：确认 blueprint 已收敛、plan 显式覆盖设计节点且阶段依赖和验收仍然成立
2. **勘察**：重新获取工作区状态，读取相邻功能和仓库现有验证方式
3. **实现**：以 blueprint 完整落地为目标，按 plan 的阶段覆盖和依赖推进，并根据代码库现实决定具体落点
4. **验证**：完成当前阶段的交付级和阶段级检查，通过后更新 plan 中的对应勾选
5. **阶段交接**：报告当前阶段结果并等待用户提交，确认提交后才实现下一阶段；最终阶段完成后核对 blueprint 覆盖、plan 验收和范围边界

### 产物

- 实现 blueprint 所需的生产代码、测试、配置和文档，按 plan 组织阶段
- 仅通过既有交付与验收勾选同步进度的 `.pome/nursery/plan.md`
- 实现结果、验证状态和未完成阻塞说明；不额外维护执行日志或状态文件

## pome-reap

当用户要求收割或归档当前需求时触发。脚本从 `.pome/nursery/blueprint.md` 提取项目名称，把 nursery 下的全部内容移动到 `.pome/archive/<日期>/<项目名称>/`；nursery 没有文件时只返回提示。

## 使用

skill 面向 [opencode](https://opencode.ai)。将需要的 skill 目录复制或链接到你的项目，例如：

```
<project>/.agents/skills/pome-seed/SKILL.md
<project>/.agents/skills/pome-plot/SKILL.md
<project>/.agents/skills/pome-grow/SKILL.md
<project>/.agents/skills/pome-reap/SKILL.md
```

这些 skill 默认由用户显式调用，例如“用 pome-seed 做需求设计”、“用 pome-plot 制定实现计划”、“用 pome-grow 按计划实现”或“用 pome-reap 归档当前需求”。
