# pome

> **pome** -- 一枚石榴。石榴的籽本就是种子，果实落地不是结束，而是下一次生长的开始。pome 循着同样的心意：把 AI 辅助开发的流程，凝结成一粒粒独立可复用的 skill。
>
> 完整设想是 **Seed -> Plot -> Grow -> Reap**（播种 -> 规划 -> 生长 -> 收割）的流程化 skill 集合。当前已落地第一粒：`pome-seed`。

## 当前 skill

| Skill | 角色 |
|---|---|
| `pome-seed` | 需求设计起点：把需求收敛为一棵功能设计树 |

## pome-seed

当用户提出新需求、需要需求拆解或功能设计时触发。它不急于写代码，而是先给出一个**设计树**：把需求拆解成功能单元，方案已明确的节点直接写方案，有分歧、缺信息或有风险的节点列出问题，整棵树交由用户逐点讨论、拍板。

### 设计树

- markdown 有序嵌套列表，节点带层级编号（1、1.1、1.2……），讨论时用编号直接定位
- 中间层节点是功能域，只起分组作用；叶子节点是能直接描述实现方案的最小单元
- 叶子节点名后的内容二选一：一句话方案（必要时附选择理由），或一个问题子列表
- 有问题的节点满足任一条件：**方向分歧**（多个互斥方向需用户拍板）、**信息不足**（缺关键信息给不出方案）、**技术风险**（依赖外部条件需用户知情确认）

### 工作流程

1. **检查**：`.pome/nursery/blueprint.md` 已存在时，先问用户继续原有需求的设计，还是开始新需求设计并覆盖原有 blueprint
2. **出树**：给出完整设计树，有问题的节点带问题子列表，供用户参考
3. **讨论**：用户用编号指定节点（如"讨论 1.3"），skill 说明待决定内容及可行选项；用户确认后把最终方案和必要理由写回节点
4. **收敛**：树上没有遗留问题时主动提示设计完成，完整展示最终设计树做最后确认
5. **落盘**：首次给出设计树时写入 `.pome/nursery/blueprint.md`，每次决策后立即更新

### 产物

`.pome/nursery/blueprint.md`，包含：

| 部分 | 内容 |
|---|---|
| 需求摘要 | 用户原始诉求的收敛表述 |
| 设计树 | 编号嵌套的功能方案与未决问题 |
| 遗留问题 | 未讨论的节点及其问题（没有则省略） |

## 使用

skill 面向 [opencode](https://opencode.ai)。将 `skills/pome-seed/` 复制或链接到你的项目：

```
<project>/.agents/skills/pome-seed/SKILL.md
```

之后在对话中直接提出需求即可触发，也可以显式说"用 pome-seed 做需求设计"。
